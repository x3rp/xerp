## T-Q2. Section 5, descriptions — what is asserted

The spec says the eight descriptions mention `rule_list`, and that the new codes are added "where a description
lists the tool's error codes". The test asserts `rule_list` in all eight unconditionally, and the new codes only
in a description that already lists `CODE_TAKEN`. Is that the intended reading, or must all eight list the codes?

## T-Q3. A partner with neither role together with other invalid fields (R8, R18)

`AC22_R18` sends both roles `false` (given, not missing), a 201-character name and `"countryCode": "Croatia"`
and expects all four keys in one response with `rules` = `partner.roleRequired`, `fields`
`["isCustomer", "isSupplier"]` — as 004 AC reports the role keys together with `code` and `name`. Only a
*missing or wrong-typed* role field is expected alone and without `rules` (AC-40).

## T-Q4. Assumptions taken from R9, R12, R15 beyond the literal ACs

- R9 "exact after trimming": with `codeChangeable` = `false`, a replace sending `" AB1 "` for the stored `AB1`
  is `200` (AC-50).
- R15: `"taxId": " HR123 "` collides with `HR123`; `"taxId": "  "` is "no tax id" and never collides (AC-70).
- R16 on replace: a replace whose code, name and tax id are all taken answers `CODE_TAKEN`; with
  `partner.codeChangeable` = `false` as well, `CODE_CHANGE_NOT_ALLOWED` (AC-63).
- R13 for replaces: six parallel replaces giving one name to six partners -> exactly one `200` (second AC-64
  test).
